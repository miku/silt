# patent — in-depth analysis

> Repository: `~/code/r14dd/patent` — "a prior-art search for your code ideas."
> Version: 0.14.1 (Rust, `edition 2021`, MSRV 1.88).
> This note is the model for **silt** (a Go, software-discovery project), so it
> focuses on the architecture patent uses to *discover software* — its data
> sources, fan-out, ranking, and the honesty guarantees that make it trustworthy.

---

## 1. What patent is

Given a plain-English **dev-tool idea** ("interactive cli to kill whatever's on
a port"), patent fans one query out across up to **19 sources** concurrently,
ranks the combined hits locally by **semantic similarity** (cosine over
`fastembed` embeddings), and hands a verdict — 🟢 **Open** / 🟡 **Crowded** /
🔴 **Saturated** — either from an LLM (local Ollama, or any OpenAI-compatible
API) or, in `--fast`, from the similarity data alone.

The core promise (its "integrity principle", repeated everywhere as a design
constraint):

> *This tool can prove something **exists**, but never that it **doesn't** — it
> only searched some sources.* Every output is scoped to "found in the sources
> checked", and sources that were selected but failed are surfaced as
> "not reached", never hidden.

The project is explicitly **modelled after `r14dd/patent`**: silt's design note
(`notes/2026-09-29-design.md`) cites it as inspiration. So the value of this
analysis for silt is *what patent does well*, *how it is structured*, and
*which patterns transfer to a Go, metadata-indexing discovery tool*.

## 3. Core domain model (`src/model.rs`)

Small, `serde`-serializable types so `--json` and the TUI render from the same
data:

- **`Query`** — the user's `idea` (full string, what gets embedded) plus
  `keywords` (cleaned tokens handed to registry search endpoints).
- **`Source`** — a 19-value enum with stable **kebab-case** serialization
  (`"crates-io"`), old PascalCase aliases kept for backward-compat, and a
  `FromStr` with friendly error listing every valid name. Used for
  `--sources`/`--exclude` and `--json`.
- **`Match`** — one piece of prior art: `name`, `source`, `url`, `description`,
  optional `popularity`, `similarity` (filled by rank), and optional
  `last_updated` (RFC 3339 UTC). `url` is the canonical identity across sources.
- **`Saturation`** — `Open < Crowded < Saturated`, **ordered** so the verdict
  can be *floored* against the data. Has an `exit_code()` (0/1/2) so scripts can
  gate on it.
- **`Verdict`** — `level`, `headline`, `gaps`, `sources_checked`,
  `sources_failed`, and a fixed `caveat`. The two source lists are the
  **transparency surface**: what was searched vs. what was selected but failed.

## 4. Data sources architecture (the heart of "discovery")

### 4.1 The `SourceAdapter` trait (`src/sources/mod.rs`)

```rust
#[async_trait]
pub trait SourceAdapter: Send + Sync {
    fn id(&self) -> Source;                          // stable identifier
    async fn search(&self, query: &Query) -> Result<Vec<Match>>;
}
```

One implementor per ecosystem, selected per-query by a keyword heuristic, fanned
out concurrently, and **not one failing source fails the run**. This is the
single most reusable idea for silt.

### 4.2 Source selection heuristics (`detect_sources`)

Rather than always hitting all 19 (slow, rate-limited, noisy), patent picks
sources from the idea's language/domain keywords:

- **GitHub and Hacker News are *always* included** — they're the
  language-agnostic index of source code and of "Show HN" launches.
- Explicit language mentions select their registry: `rust`/`crate`/`cargo` →
  crates.io; `brew`/`homebrew`/`macos` → Homebrew; `python`/`pip`/`django` →
  PyPI; `docker`/`kubernetes` → Docker Hub + Go; etc.
- **Domain sweeps** for abstract signals: `cli` casts across crates.io/Go/npm/
  PyPI/Homebrew; AI/LLM sweeps PyPI+npm; frontend → npm; backend → npm+PyPI+Go…
- **Fallback**: if nothing matched, the 3 biggest registries (npm, PyPI,
  crates.io) plus the always-on GitHub+HN.

Notable engineering details:
- `idea_contains` does **whole-word matching** (checks every occurrence so a
  leading `"go"` inside `"django"` doesn't mask a later standalone `"go"`).
- A test (`every_built_source_is_reachable_from_some_idea`) guards against a
  source that's *built but never selectable* — "marketed but never reached."

### 4.3 The 19 adapters

| Adapter | Backend | last_updated? |
|---|---|---|
| crates.io | JSON `api/v1/crates?q=` | `updated_at` |
| GitHub | JSON `search/repositories` (+ optional `GITHUB_TOKEN`) | `pushed_at` |
| npm | JSON `-/v1/search?text=` (64-char limit handled) | `package.date` |
| PyPI | **HTML scrape** `pypi.org/search/?q=` (bot-walled) | none |
| Hacker News | JSON (Algolia) | none (created_at ≠ last-updated) |
| Go (pkg.go.dev) | **HTML scrape** `pkg.go.dev/search?q=` | scraped "Published" date |
| Maven | JSON | epoch millis |
| RubyGems | JSON | none |
| Docker Hub | JSON catalog | none |
| VS Code Marketplace | JSON (needs `flags: 914`) | `lastUpdated` |
| JetBrains Marketplace | JSON | `cdate` (millis) |
| NuGet | JSON | none |
| Homebrew | JSON formulae | none |
| Packagist | JSON | none |
| Hex | JSON | `updated_at` |
| Artifact Hub | JSON | `ts` (secs) |
| AUR | JSON RPC | `LastModified` (secs) |
| Hackage | feed/header | none |
| Nixpkgs | JSON | none |

Three adapter *styles* worth copying:
1. **REST JSON** (most): fetch, `serde`-deserialize a narrow struct, map to
   `Match`. Typical, testable with `wiremock`.
2. **HTML scraping** (PyPI, Go): no keyless JSON API, so they parse the search
   page with `scraper` + CSS selectors. This is the fragile path, and patent
   invests heavily in it (see §7 honesty).
3. **Concurrent fan-out with retry and timeouts** (in `mod.rs`): each source
   gets `SOURCE_TIMEOUT = 15s`, one retry (800ms) for *transient* failures only,
   and `is_retryable` skips retrying `Unavailable` walls it can never win.

### 4.4 Query-narrowing heuristic (`narrowing_candidates`)

A recurring, *measured* insight: most registries **AND** their search terms, so
a realistic multi-keyword idea returns nothing even where matches exist. patent
tries progressively **narrowed** query strings — from the full keyword set down
to the `n` longest keywords — and takes the first that returns non-empty.
`min_terms` is per-source and empirically measured (Maven/NuGet/ArtifactHub need
1; most recover at 2). `narrowed` picks the longest keywords but **preserves
their original order** (reordering changes relevance-ranked results).

### 4.5 Dedup / enrichment (`dedup`)

Matches are deduped by **URL** (the canonical identity), keeping the first
occurrence and **filling the winner's gaps from later duplicates** —
`last_updated` and `popularity` — via `enrich`. Example: a Homebrew formula
whose homepage *is* a GitHub repo inherits that repo's `pushed_at` and stars.
Empty/whitespace URLs fall through to a `(name, source)` key (so homepage-less
formulae don't all collapse into one slot).

## 5. Ranking (`src/rank.rs`)

- Uses `fastembed` (ONNX Runtime, bundled) with **`AllMiniLML6V2`** — a small
  (~80MB, local) embedding model. Downloads once into a stable per-user cache
  dir (`dirs::cache_dir()/patent/fastembed`), not CWD-relative.
- `Ranker` splits model **init** from ranking so the expensive ~1-3s model load
  overlaps the I/O-bound source fan-out (`tokio::join!` with
  `spawn_blocking`).
- **Ranking is deliberately similarity-only** — age is reported but *never* fed
  into the score. Rationale (documented at length): an abandoned tool is still
  prior art; demoting old matches would thin the evidence the verdict is floored
  against and could turn a populated space into "Open."
- `rank_by_keywords` is a keyword-overlap scorer for `--keyword-only` (no model
  download, offline-friendly).
- `rank_async` offloads the blocking embedding work onto `spawn_blocking` so it
  never stalls the async executor.

## 6. Verdict generation + integrity guards (`src/verdict.rs`)

This is patent's *philosophical core* — the honesty machinery. Two evaluators:

1. **LLM path** (`assess`): builds a prompt with the ranked matches, sends to an
   `Llm` backend, parses the JSON verdict.
2. **Data-only path** (`from_data`, used by `--fast`): derives the level purely
   by flooring against embeddings — honest signal with zero LLM.

### The LLM backends (`llm.rs`, `ollama.rs`, `openai.rs`)

A tiny `Llm` trait (`generate` + `label`). Two implementations:

- **`Ollama`** — `POST localhost:11434/api/generate`, default model `qwen3.5`,
  `temperature 0.0`, `num_predict 512`, and **`think: false`** (measured: a
  thinking model burns the whole token budget on a reasoning trace and returns
  an empty `response`).
- **`OpenAi`** — any OpenAI-compatible `/chat/completions` (OpenRouter, Groq,
  vLLM, LM Studio…). Handles the `max_tokens` vs `max_completion_tokens` /
  `temperature` incompatibility of OpenAI reasoning models by **retrying once,
  keyed on the server's own error text** (not model-name sniffing, since
  proxies rename models).

### The integrity guards (code-level, not just prompt-level)

The prompt *asks* for honesty, but the code **enforces** it:

1. **`floor_level`**: the model's level is `max`'d against a data-derived floor
   (≥5 matches ≥0.60 → Saturated; ≥2 ≥0.55 or one ≥0.70 → Crowded). The model
   can never hand out a green "Open" over clearly-populated embeddings.
2. **`guard_headline` / `ABSENCE_PHRASES`**: any headline asserting non-existence
   ("doesn't exist", "no prior art", "completely novel", "greenfield",
   "no maintained tool"…) is replaced with a safe, scoped, data-derived
   headline. This is a deliberately *broad/conservative* backstop — a false
   positive only downgrades copy, a false negative is an integrity violation.
3. **`HEDGE_WORDS` stripping**: "no **actively** maintained tool" collapses to
   "no maintained tool" before matching, so adverb muffling can't slip past.
4. **`claims_no_match`** in the LLM eval: a close match (≥0.55) means "no direct
   match" *is* misleading, so it's replaced too.
5. **`CAVEAT`** is a fixed, never-weakened constant: *"Not proof it doesn't
   exist — only that nothing close turned up in the sources checked…"*
6. **`Open` + zero close matches → data headline**: confident LLM copy that
   reads as a green light is replaced with the honest data sentence.
7. Gaps that assert absence — or that name a known top-10 match — are dropped.

### Error taxonomy (`lib.rs::Error`)

An instructive `thiserror` enum: `Http`, `HttpClient` (failed to *build* the
client — distinct from a failed request), `Parse`, **`Unavailable`** (a genuine,
persistent wall — e.g. PyPI bot-walling — that retries can't beat, so the
fan-out skips retrying it), `LlmUnreachable`, `LlmRejected`, `Embedding`. The
distinction between retryable transient failures and non-retryable walls is
what makes the fan-out both fast and honest.

## 7. Honesty / integrity as the product's spine

The themes below appear over and over and are *the* defining trait of this
project — and the biggest lesson for silt:

- **"Not reached" is surfaced, never hidden.** Selected-but-failed sources show
  up in the header and `--json`. A thin result is explicitly framed as possibly
  "reduced coverage," not "nothing out there."
- **Stale ≠ absent.** A match is flagged `⚑` only when its *source reports* a
  date ≥2 years old. Sources that publish no date are never flagged stale —
  "an absent date is not a staleness claim." The same in the prompt: "matches
  with no date shown are ones whose source does not publish one."
- **Drift detection in HTML scrapers.** PyPI/Go return an *error* (→ "not
  reached") when a non-trivial page parses to zero results, so selector drift
  can't masquerade as "no prior art." Go even distinguishes a genuine empty page
  (its own `gopher-message` marker) from drift.
- **The verdict is scoped by construction.** Sources checked/failed are always
  the ones that actually responded; the prompt never tells the model about
  coverage that didn't happen.
- **Recency is colour, not rank.** Age never touches similarity (see §5).

## 8. Pipeline orchestration (`src/bin/patent/pipeline.rs`)

Three clean phases, shared by both CLI and TUI paths:

1. **Search** — fan out to sources *and concurrently* load/embed the model
   (`tokio::join!` a `spawn_blocking` ranker init). Logs "N matches from M
   sources in T s: <list>".
2. **Rank** — `spawn_blocking` embedding of all descriptions + cosine sort.
   Ranks to `max(limit, DEFAULT_LIMIT=50)` so the verdict/floor sees enough data
   even with a small `--limit`; truncates *after* the verdict.
3. **Verdict** — `--fast` → `from_data`; best-sim < `MIN_RELEVANCE (0.35)` →
   fallback "nothing relevant" verdict (skips the LLM to avoid hallucinating
   from noise); else `assess` with the resolved backend, **falling back to a
   search-only verdict on LLM failure** rather than aborting.

## 9. Frontends

### TUI — a clean state/render split

Patent **splits TUI logic from rendering** in a way worth copying:
- `src/tui.rs` (in the **lib**): a pure, headless `App` state machine — cursor,
  filter, sorting (similarity/popularity/name), page expansion, detail scroll,
  clipboard yank, help mode. No terminal I/O; unit-testable in isolation.
- `src/bin/patent/tui.rs`: the ratatui render layer — layout, colors per source,
  verdict panel, matches table, overlays (help, detail popup), mouse handling,
  interactive search prompt, async pipeline via a `oneshot` worker.

Rendering niceties: the **caveat is never clipped** (regression-tested at many
sizes), "not reached" line, stale `⚑` marker, and a scrollbar that tracks the
viewport offset (not the cursor). It even installs a panic hook to restore the
terminal on crash.

### CLI (`main.rs`, `cli.rs`, `config.rs`)

- `validate_idea`: rejects empty / too-vague / too-repetitive ideas (min 2
  non-stopwords), with **CJK/space-free-script acceptance** so Chinese/Japanese
  queries aren't rejected, and stopword filtering.
- Config precedence: **CLI flag > env var > config.toml > built-in default**.
  `--api-key` falls back to `PATENT_API_KEY`, config, then `OPENAI_API_KEY`.
- When stdout isn't a terminal, it **emits JSON instead of panicking** on TTY
  init.
- Shell completions via `clap_complete`; `--print-prompt` for BYO-agent
  workflows.

## 10. Testing strategy

- **Unit tests** inline in every module (model, freshness, verdict guards,
  rank cosine, narrowing heuristic, TUI state machine, word-wrap edge cases).
- **Integration tests** (`tests/`) drive every adapter against a `wiremock`
  server — **no live network in CI**. One shared `OnceLock` ranker so the ~80MB
  model downloads once across the parallel test suite.
- **Verdict/LLM tests** use mocked HTTP backends.
- Tests encode the *documented invariants* (e.g. "caveat never clipped",
  "every built source is reachable from some idea", "stale boundary at exactly
  the 2-year anniversary").

## 12. What's transferable to silt

Since silt is "a Go project to discover software, modelled after patent," these
are the concrete patterns to port:

1. **`SourceAdapter` trait + concurrent fan-out + graceful degradation.**
   One implementor per ecosystem; a failing source never fails the run; results
   carry which sources were reached/failed. In Go: an interface + `errgroup` /
   `sync.WaitGroup`, or a worker pool.
2. **Source-selection heuristics** keyed on the query's language/domain, with a
   broad-registry fallback. Whole-word matching to avoid false positives.
3. **A single canonical `Match` type** with `url` as identity, plus **dedup with
   gap-filling** from duplicate URLs.
4. **The integrity principle as code, not just copy.** Flooring, absence-phrase
   backstops, "stale ≠ absent", "not reached surfaced", scoped verdicts. For a
   discovery tool this same honesty (prove what exists, never certify absence)
   is the credibility differentiator.
5. **Stable serialization** (kebab-case source IDs, `--json`), a transparent
   header showing searched + failed sources.
6. **Query-narrowing** for ecosystems that AND their terms — try progressively
   narrowed queries, take the first non-empty.
7. **Model-cache-first**: download the embedding model once to a per-user cache;
   `--fast`/`--keyword-only` paths that skip it for offline/low-machine use.
8. **HTML-scrape drift detection**: a non-trivial page that parses to zero
   results is an error ("source not reached"), never a false empty.
9. **Clean TUI state/render split** and a pure-library core with a thin
   binary shell.

### Where silt's mission differs (from the design note)

patent **searches live** (per-query, 19 REST/HTML APIs) and returns a *scoped
verdict*. silt aims to **build a local index/map** of millions of projects and
repositories ("software that you could reuse is often packaged"), navigable by
plain text. So silt flips patent's model from *live fan-out* to *harvested,
indexed metadata* — but the *selection heuristics*, *dedup*, *honesty rules*,
and *concurrent-source hardening* all carry over directly. The
`List_of_software_package_management_systems.txt` in silt's notes is the seed
for source enumeration.
