# silt vs patent — parity report

> Run: 2026-10-26, silt at `9f90bce` against patent 0.14.1 (`8d741bd`), live,
> with `GITHUB_TOKEN` set.
> Reproduce: `go run ./scripts/parity` and `go run ./scripts/parity -embeddings`
> from the repository root.

## Summary

The harness found no unexplained differences, which is M8's "done when"
condition. On all 33 reference ideas (`scripts/parity/ideas.txt`), both
runs give the same verdict level as patent. The similarities of matches
both tools found differ by at most 8.9e-7, against a tolerance of 1e-3. No
match came from a different source in the two tools, so the dedup-order
deviation never showed up.

The harness still exited 1 in both runs, because 2 ideas differed in each.
Every difference came from a registry giving the two tools different
answers to the same request at the same moment. Rerun separately, both
tools got identical results each time.

## The differences, explained

| Idea | Run | What differed | Why |
|---|---|---|---|
| 22, haskell cabal json | embeddings | GitHub sent patent 35 results and silt 27; for this query it normally sends 50. The headline counts differ (13 and 8), the level doesn't | GitHub returned partial results |
| 25, terminal UI for JSON | keyword-only | one GitHub match only patent got | GitHub returned partial results |
| 17, vscode markdown preview | embeddings | Algolia sent patent 17 Hacker News stories and silt 19 | Algolia answered differently |
| 22, haskell cabal json | keyword-only | one of silt's `.cabal` fetches failed, so `xhaskell-library` lost its homepage (`http://code.google.com/p/xhaskell-library/`) and synopsis, and got the Hackage page as its URL | a one-off failed fetch; patent falls back the same way |

How each was checked:

- **GitHub, ideas 22 and 25.** The raw match counts in the logs show that
  both tools got fewer GitHub results than usual for idea 22, and different
  ones. Afterwards, sending idea 22's query to the search API four times
  (`haskell cabal library parsing json in:description,readme`,
  `per_page=50`) gave the same 50 results each time, with
  `incomplete_results: false`. Rerun with `--sources github`, both tools
  found the same 35 matches for idea 22 and the same 1 for idea 25. With
  embeddings, idea 25 was identical in both tools anyway.
- **Algolia, idea 17.** patent's `hacker_news.rs` and silt's
  `hackernews.go` try the same query candidates and filter the same way, so
  neither drops a story the other keeps. Algolia returns 19 stories for the
  idea on repeated calls, including the two that only silt had (items
  34206333 and 39682183). Rerun with `--sources hacker-news`, both tools got
  19.
- **Hackage, idea 22.** The `.cabal` file is plain ASCII with ordinary
  `Homepage:` and `Synopsis:` lines, and both tools parse it the same way. In
  the embeddings run, silt got the homepage and synopsis.

Also seen: in the keyword-only run, GitHub failed for idea 17 in both tools,
and both reported it as failed, so that run still agrees.
