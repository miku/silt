# Software Discovery in the Generative AI Era

Large language models are capable of writing code, allowed them to be used for
software development and analysis. When writing code get significantly cheaper,
what happens to software discovery?

Since GPT-2 in 2019, and Codex in 2021 LLM assisted coding has improved
significantly, up until a point where benchmarks like HumanEval seem to be
solved. In 2026, agent harnesses and multi-agent swarms can run multi-hour
workflows to implement complex software projects.

The number of software publications overall is on the rise too, with the
popular Python Package Index (PyPI) nearing 1M projects, up from about 100K
less than ten years ago.

For a set of smaller projects, it would be feasible today to describe its
functionality is, put it into an index and then generate the software package
on the fly, when a user retrieves the item. A project like
[wishful](https://pypi.org/project/wishful/0.2.2/#history), released in 2025,
demonstrates this on a small scale:

> wishful turns your wildest import dreams into reality. Just write the import
> you wish existed, and an LLM conjures up the code on the spot. The first run?
> Pure magic. Every run after? Blazing fast, because it's cached like real
> Python.

In 2030, will we be able to put a spec into a text file and have it synchronize
it with code? What role will existing software play? Will is be, akin a pyc
file, frozen LLM time?

The space of software is vast, as most symbolic spaces. Classic software
development was an optimization problem, where the constraints were time,
developer attention and a commercial viability.
