# Software discovery, in three essays

Draft topics and abstracts for **upsweep.org** — the prose side of the
project, meant to sit beside the tool. Each essay is anchored in what the
tool and its notes actually ran into: the growth numbers, the integrity
rule, the "Open," "Crowded," "Saturated" verdict, the walled PyPI, the LLM
that invents package names, the whole-MiniLM-L6-v2 embedding sitting in a
static binary. The intent is not to advertise a tool but to say something
true about how software is found — in general, and in the age of AI.

Suggested order for serialisation: **1 → 3 → 2** (set up the honest "search
is ephemeral" frame first, then the editorial turn about not trusting the
LLM, then the forward-looking map of what a real index could be). Price and
length are for a ~1,200–1,800 word longform piece; each can be trimmed to a
shorter "notes from the build" post.

Two later ideas, added to the brief, cut across all three and are worth
naming explicitly so they don't get lost:

- **Search is becoming a delegation, not an act.** In the age of cheap code
generation the *user* may stop searching altogether — an agent searches on
their behalf. Discovery then stops being a moment and becomes a capability.
- **The index is no longer constrained by the world.** We can build an
*artificial* software index — every idea written down and described, the
code generated on the fly. This inverts discovery's oldest axiom: that the
map describes what already exists. What does discovery mean when the map
*creates* its territory?

These two belong in the third essay's forward turn (and echo back into the
first's framing). See the "Weave-in" note under essay 3.

---

## 1. "Software is not lost yet — it's just unindexed"

**Short abstract.**
Finding software was never a physics problem, it was a bookkeeping problem —
and the bookkeeping is 40 years behind the shelves it describes. Search
engines and LLMs treat "what exists" as something to guess; the registries
that *know* (npm, PyPI, crates.io, Maven Central, and forty others) are
each a private card catalog with its own vocabulary, its own wall, and no
grand index uniting them. The essay starts from a strange, recent failure
mode: a tool that is forbidden, by its own design, from ever telling a user
"this idea doesn't exist" — because it has only *searched*, never *known*.
That honesty rule, applied to a map that should be carved in stone, is the
essay's spine.

**Weave-in (both new ideas, lightly, up front).** Open with the honest failure
mode, then widen: in a few years the question "does this exist?" may stop
being asked to a search box at all — an agent asks it on your behalf, and
worse, the agent may be content with an *invented* answer, because the
cheapest way to "make it exist" is generation. That turns the essay's spine
— the tool that refuses to claim absence — from a curiosity into a warning
about delegation: if the searcher is an agent, who holds it to the proof? The
index-is-artificial idea belongs here too as the far shore: a map that can
grow its territory on demand is a map that can lie in a new way. Keep both
brief here; essay 3 earns the full argument.

**Notes (from the repo).**
- The integrity principle: *"can prove something exists, but never that it
  doesn't — it only searched some sources."* Every verdict is scoped to
  "found in the sources checked," and sources that failed are reported as
  such.
- The evidence that the bar to beat is trivial: people find software via web
  search and colleagues (Hucka & Graham); general web search beats
  code-specific engines for whole systems (Sim *et al.*). Discovery tools
  are underused not because they're bad at ranking but because they're bad
  at *coverage* — and nobody can tell how bad, because coverage is unstated.
- The scale, fetched directly from `ecosyste.ms` (2026-10-26): npm ≈ 6.0M
  packages, Go modules ≈ 2.5M, Docker Hub ≈ 1.0M, PyPI ≈ 945k, NuGet ≈ 873k,
  Hugging Face ≈ 773k, Maven Central ≈ 734k, Packagist ≈ 525k, crates.io ≈
  366k, RubyGems ≈ 214k. Ten registries, ~14.3M named things, each discoverable
  only inside its own garden.
- The concrete wall: PyPI's search is bot-walled, so in the tool PyPI is
  "always not reached." A search that omits the single largest Python
  registry must *say so* — and the tool does. That's the rare behaviour being
  argued for here.

## 2. "Don't let the model tell you the answer"

**Short abstract.**
The most dangerous sentence in software right now is "there's a package for
that," spoken by a model that has never seen a registry. It sounds helpful
and it is a hallucination with a supply chain attached: studies of code
generated by 16 LLMs found 5–22% of the packages referenced simply do not
exist. This essay argues for an *epistemic* fix, not a statistical one: the
answer to "does this exist" must never come from a model that was trained on
rumours of packages, but from a source that has actually held the thing. A
model can rank, summarise, doubt, connect — and then it must be caged: it
may raise a verdict but never lower it, and it may not utter the word
"doesn't exist." The essay is a case study in building a guardrail where the
stakes are not a wrong answer but a wrong *kind* of answer.

**Notes (from the repo).**
- Spracklen *et al.* 2025 ("We Have a Package for You!"): 576,000 generated
  samples, ≥5.2% (commercial) / 21.7% (open) of referenced packages don't
  exist → 205,474 unique hallucinated names, a real attack surface.
- Latendresse *et al.* 2024: ChatGPT uses libraries ~10% more than humans
  but 14.2% of recommendations carry unmentioned copyleft licences and 6.5%
  don't work as installed. The model is good at names, bad at *properties*.
- The tool's actual cage (from `verdict/assess.go`): a broad backstop list
  of absence phrases; the LLM's level is `max(model, data-floor)`, never
  lower; absence and "no match" headlines are replaced; gaps claiming
  absence are dropped; the caveat is never clipped. Rationale recorded
  verbatim: *"a false positive only downgrades the copy to a safe scoped
  headline, whereas a false negative is an integrity violation."*
- A delightful, telling bug: a *thinking* model behind an OpenAI-compatible
  API spends its whole 2,048-token budget on reasoning, produces empty
  content, and so silently hands back the data verdict. The guardrail does
  the work precisely when the model is most confident.

## 3. "A map of every tool, and the holes between them"

**Short abstract.**
Point search is a verdict you pay for per query. What software discovery
really wants is a map: a harvested, locally held index of what exists, that
you can walk at the speed of thought — find underserved areas, compare
spaces, ask "what's missing here" the same way you ask "what's here." The
essay argues that the *verdict* and the *map* are different products, and
that we should stop conflating them. It is both a modest proposal (a
full-text-plus-vector index of package metadata, with provenance — which
source, harvested when — attached to every row) and an honest confession
(the three-level verdict — Open, Crowded, Saturated — is coarse, and its
LLM overlays can't see the coverage gaps baked into it). Then the essay
earns its forward turn, with the two ideas that reframe discovery in the age
of AI: *(i)* search is becoming a delegation, not an act — an agent searches
for you, gates on the exit code, and has weak incentive to search honestly
when it can generate a replacement instead; and *(ii)* the map no longer has
to reflect the world — an *artificial* index can write down every idea and
build the code on the fly, which inverts discovery's oldest axiom: the map
now creates its territory. To end: what "in the age of AI" actually changes
— not retrieval, but *who searches*, and *what the map is allowed to be*.

**Weave-in (the essay's payoff; both new ideas live here).**

1. **Delegation as the new normal.** With cheap code generation, the human
   leaves the loop and the *agent* searches. Discovery stops being a moment
   ("let me see if this exists") and becomes a capability ("whenever you
   need X, find or build it"). Two consequences worth arguing: (a) the
   verdict's audience is no longer a person with a sense of taste but a
   program that gates on an exit code — Open/Crowded/Saturated must survive
   being read by software, which is exactly why the tool's verdict is
   already one byte; and (b) an agent that can generate a replacement has
   *weak incentive to search honestly* — it will take the cheapest path to
   "solved," and "just build a fresh one" is often that path. Honest search
   becomes the thing that has to be *enforced* on an agent, not expected of
   it. This reframes the whole tool: it is not a better search box, it is a
   discipline imposed on a searcher that would rather not search.

2. **The artificial index, and discovery's inverted axiom.** Once code is
   cheap, the index stops needing to reflect the world: write down every
   idea, describe it, and generate the package the moment it's asked for.
   The map no longer *describes* its territory — it *creates* it. What does
   discovery mean then? The essay should argue it changes meaning but does
   not disappear: (a) you still need to know what *shape of thing* exists in
   an idea-space, even if the instances are generated — the catalog of
   *possibilities* is exactly what upsweep's verdict (Open/Crowded/Saturated)
   is already measuring, just for real artefacts; (b) crowding becomes a
   property of *ideas*, not of shipped code — an idea-space can be saturated
   even where nothing has shipped, because "someone could build this in an
   afternoon" becomes a real signal; and (c) a hard rule carries over
   unchanged and grows stronger: the tool / agent must still only report
   what it has actually seen, because in an index that can fabricate its own
   landmarks, "I saw it" is the one thing generation can't forge. Provenance
   — which source, when, and *real or made* — stops being a nice-to-have and
   becomes the entire trust model.

   End on this: in the age of AI, `exists` becomes a *modal* word. The tool
   that can only say "I checked these nine, here's what came back" is
   suddenly not a worse search — it is the only honest contract we have left
   once everything else is free to hallucinate.

**Notes (from the repo).**
- Two real, observed artefacts that a point search can't see but a map can:
  1. *PyPI is walled* → the idea "a python pandas data pipeline" comes back
     **Open**, a pure coverage artefact, because the biggest Python
     registry wasn't reached.
  2. *MiniLM is English-only* → 端口杀手命令行工具 ("port-killer CLI", in
     Chinese) returns **Open**, while the same idea in English is Saturated.
     The empty map is not emptiness; it's a hole in the index.
- The verdict is coarse and the floor is naive: three thresholds on a
  symmetric sentence-similarity model, calibrated once and with no record of
  how. "Three levels are fine as an exit code, but you can't rank ideas by
  it or compare areas" — from the verdict notes.
- The growth story for the "map" framing: JavaScript transitive deps grew
  60% in a year; a minority of packages drive most updates; reuse at the file
  level was already >50%. The map should describe a moving, connected
  territory, not a card catalog's static shelf.
- Asymptote of the essay — the designed future in `notes/todo.md` M9: "a
  harvested index instead of a live fan-out," with honesty rules that carry
  over as *provenance*: which source, and how fresh.

**And what the two new ideas would do to the project itself** (worth deciding
before writing, because they change the tool's stated goal):

- *Delegation* points upsweep's future squarely at the **machine-readable
  contract**, not the human UX. The exit code (0 Open / 1 Crowded / 2
  Saturated) is already an agent-facing API; the honest next step is a first-
  class "ask an agent" mode — `upsweep` called from a build/agent loop, with
  a machine flag that says "I'm being asked by software," so the caveat and
  `sources_failed` stay mandatory even when no human will read the headline.
- *Artificial index* suggests a second, deliberately *distinct* product on
  the same site: not the tool tonight, but the visible provocation — an
  "idea index" where Open/Crowded/Saturated is measured over *generatable*
  possibilities, kept strictly separate from the tool's "what actually
  shipped, checked against these nine sources." The two must never share a
  verdict row; that separation *is* the argument of essay 3. A shape the
  series could take: essay 1 (the honest failure mode) → essay 3 (map vs.
  verdict, ending on delegation + the inverted axiom) → essay 2 (the
  guardrail) → then a fourth, optional essay that proposes the artificial
  index in full.
