# SIL1: design

> Software reuse is finally here but comes with risks. [R. Cox, 08 July 2019,
> ACM Queue](https://queue.acm.org/doi/10.1145/3329781.3344149)

A small, fast tool for software discovery. We find similar tools for your ideas
in millions of projects in a few seconds.

## Inspiration

Patent

> patent — a prior-art search for your code ideas.
> [docs](https://docs.rs/patent/latest/patent/),
> [github](https://github.com/r14dd/patent)

> Takes a plain-English dev-tool idea and searches the open-source ecosystem —
> crates.io, npm, PyPI, GitHub, Go, Maven, NuGet, RubyGems, Docker Hub,
> Homebrew, Packagist, Hex, Artifact Hub, AUR, Hackage, Nixpkgs, the VS Code
> Marketplace, the JetBrains Marketplace, and Hacker News — for prior art, then
> gives an honest, scoped verdict on whether it’s already been built. The exact
> set searched is chosen per query; whichever sources actually responded are
> always surfaced.

> Integrity principle: this tool can prove something exists, but never that it
> doesn’t — it only searched some sources. All output is scoped to “what was
> found in the sources checked.”


## Outline

There are two ways to approach this:

* [ ] go out at query time to the indices and catalogs and run queries, aggregate and rank them locally
* [ ] build a index of software and query that

We start with the first approach, because it is much cheaper, real-time and
still useful. For a more in-depth tool, we would want to learn more about each
software package and for that we could just as well build an offline index.
That requires storage and compute for an initial version (and some for the
increments).
